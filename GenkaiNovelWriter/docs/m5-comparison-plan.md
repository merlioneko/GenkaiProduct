# M5 比較計画

2026-10-25に生成前の方針を記録。要求の正本は[SPEC](../SPEC.md#acceptance-m5)、実行結果は[MILESTONES](../MILESTONES.md#evidence-m5)。この計画だけで品質・速度の合否は確定しない。

評価者は「ユーザ」。Concept照合の独立試験は今回は行わず、検出性能未検証として人手で原入力と照合する(D48)。Codexは条件の記録、採取、機械的集計、引用位置の整理を補助し、人手の採点や許容速度を代行しない。

入力は `concrete_01.txt` と `vague_01.txt`。一発生成と生成部分の一括実行を各入力2回、計8件新規採取する。旧ベースラインは各入力1件ずつで、正確な量子化・ロード条件の追跡も不足しているため比較母集団に含めない。M4の2件も事前計画・評価者・暫定基準の記録前の動作確認であり、今回へ転用しない。

モデルはM4と同じQwen3.6-35B-A3B Q4_K_MとGemma 4 26B-A4B Q3_K_M。執筆と一発生成は同じGemma・思考設定 `null` を使う。正確なキー、量子化、実ロード長16384、ロード時にAPIが返す設定は `prepare` の実観測で `preflight.json` へ保存し、そのハッシュを `plan.json` に含める。Q4基準でのGemmaの評価とは扱わない。

順序は具体入力B1→P1、曖昧入力B1→P1→P2→B2、具体入力P2→B2(B=一発生成、P=一括生成)。各入力で方式の先後を入れ替える。乱数シード・サーバ既定のサンプリング設定はクライアントから固定せず、この限界を残す。

各試行前にロード済みLLMを解放し、ロード数0を確認する(D46の専用運用)。試行間のリセット時間は別扱いとし、タイマーは生成関数を呼ぶ直前から最終成果物の保存完了までとする。初期JITロード、Concept→Writingの切替、全生成・結合・評価票保存を含む。OSのファイルキャッシュは消去しないため、ロード数0を完全なコールドキャッシュとは呼ばない。

呼び出し後のモデルAPI観測時間は経過時間に含め、別に観測秒を記録する。gatewayのモデル準備(状態取得・明示アンロード)は元処理を変えず外から計測し、LLM呼び出し時間の内数として記録する。JITロード単独の時間は分離できないため、LLM呼び出し時間に含む。経過時間と呼び出し時間の合計を混同しない。観測の負担とCPU/GPU配置情報の不足を速度判断に併記する。

コード・プロンプト・入力・バックエンド公開設定・Python/依存バージョンを計画へ固定し、試行前後に照合する。本文・Concept・Plot・シーンは編集しない。設定変更、失敗、中断、実ロード条件の不一致は台帳に残し、自動的な成功扱いや失敗試行の上書きを行わない。既存stageの01上書きは変更せず、この比較はstage/writeの再実行を使わない(D47)。

生成前の暫定基準は当時のSPECの成功基準案を使う。要素欠落・順序違反0、ジャンル/トーンの適合、設定矛盾0、通読で気づく物理的破綻0を評価する。600字未満は警告、伏線放置と非陳腐性は観察として記録する。ユーザは全8件を原入力から照合し、各試行の根拠と方式内のばらつきを記入して、U1・U7・U8を判断する。基準を変更した場合は変更理由と事前基準との差を残す。

`status.md` は機械的な採取状況と本文リンク、`human_review.md` は人手の比較・最終判断、各一括生成の `07_eval.md` は作品別の詳細評価欄。評価は採取後に記入する。評価済みファイルを上書きしない。少数試行から一般的な優位性を断定せず、U1が否定・保留ならM6へ自動移行しない。
