## Concept照合の初回試験

[正解候補8資料](../test/fixtures/remediation/concept-verification.json)を原入力・Concept・正解候補の順にユーザが確認し、2026-10-27に採取を承認した。以下は採取前に固定した計画。

- 全8資料は今回作成した合成例。M2の実出力の複製・既知例の原文として扱わない。主体逆転と構想本文だけの改変は、M2の既知の失敗形を参考にした。
- missing/reordered/weakened/alteredの各分類に正常な言い換え1件と異常1件。正常例は照合上の意味保持を扱い、生成プロンプトの逐語転記遵守の評価とは分ける。
- 正解は欠陥の原因単位で数える。異常例の主分類と同じ原因の別表現を重複TPへ加算しない。別分類の妥当な指摘は人手で理由付き記録し、自動FPとしない。
- 各資料2回、計16呼び出し。現行Qwen・thinking=nullと、C反映後の現行Concept照合プロンプトを固定して測る。追加の検出改善指示は初回に加えない。
- 採取前に資料・正解・コード・プロンプト・公開設定のSHA-256、量子化・実ロード長・観測時刻・評価者・呼び出し順を新しいstudyへ保存する。条件が変わったら同一計画の採取を停止する。
- 生出力・項目別エラー・calls・所要時間を残す。正解との対応付けをユーザが確認し、TP/FP/FN/失敗/時間を集計する。失敗を見逃し0や指摘なしへ置き換えない。

正常例で新しい問題が見つかった場合は、採取前に正解候補を修正する。採取後の正解変更は理由と変更前後を記録する。16呼び出しは初回観察の規模であり、一般的な性能保証の基準ではない。

見逃しが再現した分類だけ改善候補を作り、別の最終確認資料を用意して比較する。今回の8資料で調整したプロンプトを同じ8資料だけで合格としない。スキーマ拡張や別モデル採用は初回の対策にしない。
