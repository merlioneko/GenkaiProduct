## M1: 接続基盤・前提検証・ベースライン

最もリスクが高いのは、LM Studio上で2モデルが想定どおり動くかどうかである。パイプラインの実装より先に確認する。

### 作業(コミット単位)

1. **リファクタ**: `util/gateway.py` をOpenAI互換クライアント1クラスに統合する。`LmStudioGateway` / `OpenRouterGateWay` を廃止する。Tavilyへのimportを除去する。ミュータブルなデフォルト引数(`history: list = []` など)を `None` に変える。
2. **機能**: `util/config.py` で `.env/backends.json` を読み、フェーズ名からモデル・思考設定を引けるようにする。
3. **機能**: `util/log.py` で、LLM呼び出しごとに `calls.jsonl` へ記録する(フェーズ、モデル、入力/出力トークン、所要時間)。
4. **機能**: `main.py baseline --input <file>` を実装する。
5. **検証スクリプト**: `test/verify_backend.py` を作成し、下記の検証を実行して結果を出力する。

### 検証項目

| 対象 | 検証内容 | 記録先 |
|---|---|---|
| U2 | Qwen・Gemmaそれぞれで、思考モードをリクエスト単位でオン/オフできるか。オフ時に `content` に思考タグが含まれないか | SPEC.md の U2 を確定事項に移す |
| U3 | Qwenで、SPEC.md のPlotスキーマを使った構造化出力を10回実行し、スキーマ違反の件数を数える | 同上 |
| U4 | Qwen → Gemma → Qwen の順に呼び出し、JITロードでモデルが切り替わるか、前のモデルが解放されるか | 同上 |
| U7 | 各モデルの生成速度(tok/s)を計測する | SPEC.md の U7 に実測値を追記 |

### 完了条件

- `baseline` コマンドを、ローカルのGemmaで `concrete_01.txt` と `vague_01.txt` について各2回実行し、`creations/baseline-*/baseline.md` が4件保存されている。
- `calls.jsonl` にトークン数と所要時間が記録されている。
- U2・U3・U4の検証結果がSPEC.mdに反映されている。
- `main.py` の実行経路でTavilyのキーファイルがなくても起動できる。

### 検証結果が否定的だった場合

| 結果 | 対応 |
|---|---|
| U2 不可(思考を切れない) | 思考タグを後処理で除去する方式に変え、SPEC.md を更新してから M3 に進む |
| U3 違反が多い | スキーマの簡略化、または Structure のモデル変更を検討する。SPEC.md を更新してから M2 に進む |
| U4 不可 | `lms` CLI で明示的にロード/アンロードする方式に変える |

実際の結果(2026-09-18 に SPEC へ反映):U2 は切り替え不可だったが、思考内容が `content` に混ざらず `reasoning_content` に分離されるため、後処理での除去は不要と判断した(D37)。U3 は10回中違反0件で、スキーマの簡略化もモデル変更も不要(D38)。U4 は不可で、`lms` CLI による明示的なアンロードに変えた(D39)。

## M3: Writing(B'方式)・再開・Assemble

着手条件: M2 完了(2026-10-13 承認済み)。思考モードの扱いは D37 で確定済み。

### 開始時の確認と引き継ぎ

- 既存 `.venv/Scripts/python.exe` は参照先の Python が利用できず起動しない。M3 開始時に通常の CLI を実行できる環境を確認・修復する。今回のオフラインテストは同梱 Python と既存依存ライブラリで確認したもので、仮想環境の修復完了を意味しない。
- 実機実行では LM Studio のロード時コンテキスト長16384を確認し、M2 のタイムアウト実績を踏まえて `--timeout 1800` を用いる。`thinking` は D37 に従い `null` とする。
- `beats` の文言・呼称・メタ記述が本文へ不適切に流用されないかを Writing 出力で確認する。構想内部の矛盾と Concept 照合の検出力は、SPEC.md の既知の課題として引き継ぐ。
- 既存の編集済み `concrete_01` は M3 の動作確認に利用できる。M5 の U1 比較では、新たに無編集の出力を採取する。

### 作業(コミット単位)

6. **削除**: `extract_tail` / `extract_head` / `check_border` / `elaboration` を削除する。

### 実装・環境確認(2026-10-19)

- 既存 `.venv/Scripts/python.exe` が Python 3.12.0 で起動し、Pydantic 2.13.5・OpenAI SDK 3.14.1・httpx 0.28.1 を利用できることを確認。以前の起動不能は再現せず、仮想環境の再作成は不要だった。既存87テストは成功。
- `util/models.py` でロード状態取得・旧モデルの明示アンロード・解放後の再確認を実装。実クライアントの local 呼び出しに適用し、remote は対象外とした。
- `novel/context.py`・`novel/phases/writing.py`・`prompts/writing/system.md` と `stage writing` / `write --from k` を実装。先行本文はファイルから全文読み、各シーンの完成後に保存する。全シーン成功後に Assemble・字数集計・600字未満の警告を行う。
- 壊れた Plot・範囲外の番号・欠落した先行本文は退避前に停止する。API エラー時は生成済みシーンを残し、入力を切り詰めない。ログの `scene` でシーン番号を識別する。

- オフラインテスト108件すべて成功。実行ログは `creations/m3-offline-tests.log`、実機手順は `test/README.md` 第9節に記載。
- LM Studio API への通信は実行環境のネットワーク制限を外した実行で確認できた。設定の `thinking` は全フェーズ `null`、記録コンテキスト長は16384。従来と同じ Gemma Q3_K_M を設定済み識別子で明示ロードし、API で実際のロード長16384・ロード数1を確認して Writing を開始した。保存済み識別子と現在のモデルキーは完全一致しないため、別環境での実行前にも識別子を確認する。
