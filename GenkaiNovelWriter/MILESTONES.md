**D37 の根拠(思考モード)**

- 思考内容は `content` から分離される。本文に `<think>` は現れず、`reasoning_content` フィールドに入る。Qwen・Gemma とも同じ。
- `chat_template_kwargs` によるリクエスト単位の切り替えは効かない。`{"enable_thinking": false}` を付けても `reasoning_content` は出続け、出力トークン数もオン指定時と変わらない(Qwen 963 / 1008 トークン。Gemma は false 指定で 2646 文字の思考)。存在しないキー名を入れてもエラーにならないことから、LM Studio が `chat_template_kwargs` を破棄していると見られる。
- Qwen のチャットテンプレート自体は `enable_thinking is defined and enable_thinking is false` の分岐を持ち、未定義のときは思考ブロックを開いたまま渡す。観測された挙動はこの未定義側と一致する。つまりテンプレートではなくサーバ側で渡っていない。
- リクエスト側から切り替える方法は、LM Studio が `chat_template_kwargs` を通すようになるまで存在しない。モデルのロード設定側で切る方法は未検証。いずれも本文に思考が混ざらない以上、着手をこれに待たせる理由がない。

**D38 の根拠(構造化出力)**

- `novel/schema.py` の Plot スキーマで10回生成し、スキーマ違反0件・APIエラー0件(`verify-20260917-193837/schema-01..10.json`)。
- 出力は平均1665トークン、13.0 tok/s。最大は3633トークン(schema-06)で、そのときも違反なし。
- 思考が出たまま(D37)の状態での結果である。思考をオフにした状態は測っていない。

**D39 の根拠(モデルの自動解放)**

- Qwen → Gemma → Qwen の順に呼び、3回とも `/api/v1/models` の `loaded_instances` に両モデルが残った。JITロードによる前モデルの解放は行われない。

- 2モデルが載ったままの状態で、空きRAMは 64GB 中 300〜400MB しかない。GPU の専有メモリは約16.7GB。M3 で3フェーズ目を足す余地はない。

**U6(モデル割り当て)に関わる執筆モデルの安定性**

- Gemma が LM Studio の出力パーサ(`peg-gemma4`)に適合しない出力を返し、生成が HTTP 400 で落ちることがある。エラー本文は `The model produced output that does not match the expected peg-gemma4 format`、GUI のログ上は `Channel Error`。
